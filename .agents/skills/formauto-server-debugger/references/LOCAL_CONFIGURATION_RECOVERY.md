# Explicit local configuration recovery

Use only when the user explicitly requests recovery of FormAuto application configuration from the configured production VPS to local. This mode reads production and writes local; it does not authorize changes to production, deployments, provider calls, payment requests, or submissions.

## Scope and handling

1. Read `docs/ai/DEPLOYMENT_GUIDE.md`, `docs/ai/ENVIRONMENT_SETUP.md`, and the source that consumes the requested configuration. Resolve the Windows SSH settings as described in `SKILL.md`.
2. Inventory configuration names and service/key-ring metadata first. Read only the application values needed for the requested recovery. Prefer a whitelist from the running API environment; a restricted env file may require privileges unavailable to the SSH user. Do not weaken server permissions or extract unrelated service secrets.
3. Capture SSH output inside a local process and parse it without returning raw output to tools/chat. Never print secrets, secret prefixes/suffixes, key XML, SQL credentials, or personal token records. Return only field names, presence, and validation results. Do not put secret values in command arguments, checked-in scripts, reports, or documentation.
4. Before writing, verify a repository destination is ignored by Git, or use protected storage outside the repository; keep either outside cloud-sync folders. Preserve existing local configuration. Restrict local secret files/directories to the current user and required system administrators. Use `src/FormAutoHub.Api/appsettings.Development.json`, `apps/web/.env.local`, or a task-specific ignored local directory for recovery snapshots. Keep the runtime local key ring in durable protected storage such as `%LOCALAPPDATA%/FormAutoHub/DataProtection-Keys`, not a temporary recovery folder.
5. Use the local SQL instance and a separately generated local JWT signing key. Do not copy production SQL credentials, the production JWT signing key, SSH/GHCR/deploy credentials, application sessions, or other users' access/refresh tokens into the local runtime. Google client configuration and explicitly requested provider credentials may be restored within scope. Use localhost URLs and report that Google must allow the local origin/redirect URI.
6. Provider secrets are stored encrypted in the application database, not necessarily in env files. If restoring them is requested, select only the required provider rows through a read-only query. Transfer the required key ring through an in-memory SSH stream into an isolated ignored local directory; do not mount the production ring as the ordinary local runtime ring.
7. Decryption must use the original Data Protection application discriminator and purpose from runtime/source evidence. Key files alone do not prove decryptability. If keys are missing or decryption fails, stop that secret's recovery and report `Blocked`; do not erase ciphertext. Retained local keys may be checked for ciphertext created by the prior local app, without removing the old keys. For local persistence, re-encrypt recovered values under the local runtime's own key ring and discriminator. Normalize the absolute content-root path with the runtime's path separators and trailing separator: mixed `/` and `\` can produce a different discriminator on Windows. A helper's encryption roundtrip alone is insufficient; verify a read through the running API. Preserve unrelated rows, accounts, sessions, and data; do not enable live payment activity as a recovery side effect.
8. Do not start an API against an existing database until migration history has been compared with source and any required local mutation is authorized. Verify configuration loading and the smallest applicable local smoke. Distinguish restored configuration from verified Google/AI/PayOS integration behavior.

## Closeout

Report restored field names and destination paths without values, skipped/blocked secrets, Git ignore checks, production read-only status, and runtime checks actually executed. Do not claim GitHub Actions variables, Google allowlists, or server configuration changed unless the user separately authorized and those changes were executed.
