- `.agents/skills/` is the maintained distribution. `.claude/skills/` is a generated byte-identical mirror, not a second editable source. Use `python scripts/agent-skills.py --sync` after authorized package changes, then `python scripts/agent-skills.py --check`.
- [Superpowers manifest](../../../.agents/superpowers-source.json): 15 skills, v6.4.2, commit `8ca22dba9a94f28898bbce59f2537ff4d87c747d`, originally obra/superpowers; byte-preserving import from the approved Minh Khuê local snapshot.
- [UI manifest](../../../.agents/ui-skills-source.json): Impeccable and UI UX Pro Max, pinned locally maintained snapshot with upstream candidates recorded; no claim of pristine upstream release identity. Import paths are provenance, not runtime dependencies.
- Keep bundled [Superpowers license](../../../.agents/SUPERPOWERS-LICENSE), [UI notices](../../../.agents/UI-LICENSES) and [modern-screenshot notice](../../../.agents/MODERN-SCREENSHOT-LICENSE). Never edit vendored bytes to customize behavior or make checks green.
- [.gitattributes](../../../.gitattributes) disables line-ending conversion for package/mirror/notice bytes so manifest hashes survive Git checkout. Local `.impeccable/config.json` disables automatic update and staleness checks; no global caches/hooks are needed for the scoped context pilot.
- Change package version only within authorized scope: review source/version/license, script/network effects, hashes, rollback, routing and affected pilot. Never execute every bundled script as an installation step. A pin verifies integrity, not safe behavior of every script.
- Retired generic FormAuto skills are removed from active discovery; historical prompts are not executable guidance. Seven retained specialists are project-owned, so fix their stale references at source and regenerate the mirror.

## Project overrides of upstream methods

1. Session/user permission and project scope take precedence. Do not auto-install hooks, modify global Codex/Claude config, create recurring work, commit, push, merge, deploy or delete worktrees/evidence because a skill suggests it.
2. Load only relevant skills. Runtime catalog is authoritative for available tool schema/provider/model. Explicitly reading SKILL.md is valid when auto-discovery is absent, but is not proof of auto-discovery. Names such as `superpowers:writing-plans` refer to the local `writing-plans` package, not a promise that a plugin is installed.
3. Reuse approved discovery and plans. This approved docs/packaging migration may execute inline in its current dirty checkout with a preserved baseline; do not manufacture approval prompts, commits or worktrees to follow upstream examples. For future code tasks choose isolation by task/ownership; never conceal uncommitted dependencies.
4. Store durable plan/decisions/validation in the task dossier under paired docs, with actual approval and next action. Upstream plan paths and Bash ledger helpers are optional adapters; do not run incompatible helpers on Windows or delete durable records as skill scratch.
5. Test by impact. Docs edits do not require artificial TDD; runnable behavior still requires project runtime gates. Review thresholds, re-review after fixes and resource preservation follow [quality](QUALITY_GATES.md) and [execution](EXECUTION_RULES.md), overriding upstream limits on fix/review loops or cleanup.
6. Impeccable is the UI method, UI UX Pro Max is supporting research, Stitch is an optional design integration. The existing frontend guide/design artifacts and accepted product UI remain authoritative. Do not create PRODUCT.md/DESIGN.md, change tokens/framework or replace an accepted UI just to satisfy a generic initializer; use approved project docs as context and record any adapter need. No automatic update checks/hooks/pins; inspect a requested script before execution.
7. Source reading follows [source rules](../SOURCE_STRUCTURE_AND_NAMING_RULES.md): maps route, current symbols and complete implementation/dependencies/tests establish behavior.

## Actual commands and targets

Run only what the change requires, from the correct cwd:

- Repository: `python scripts/agent-skills.py --check`; `dotnet build FormAutoHub.sln -c Release`; `dotnet test FormAutoHub.sln -c Release`. EF tool pin is in `.config/dotnet-tools.json`; migration commands need the authorized test DB.
- `apps/web`: `npm run lint`, `npm run build` (includes `check:colors`), `npm run test:auth`; `npx playwright test <affected-spec>` for regression.
- `run-local.bat` / `npm run dev` starts API 7039 and web 3020 and can install missing frontend dependencies. It is not a read-only check.
- Default Playwright config starts web 3000 and may reuse an existing server locally; verify ownership/target first. SEO config uses an explicitly started target, default 3034. Auth/browser test files can mock APIs; inspect the spec before claiming integration.
- CI currently configures backend build/test, web lint/build, container builds. Auth/Playwright/docs checks are not configured in that CI. Release/deploy triggers and actual protection settings must be checked before remote work; YAML presence does not prove a run passed.
